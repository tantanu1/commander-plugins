# Amazon S3 / S3-compatible

Browse Amazon S3 buckets and S3-compatible storage (MinIO, Cloudflare R2, SeaweedFS, ...) like a
folder. Also shows an `s3` drive in the drive bar and Alt+F1/F2.

## How to use

- Open the `s3` drive (drive bar, Alt+F1 / Alt+F2): it lists your AWS profiles, a profile lists
  its buckets. Or type `s3://<profile>/<bucket>/folder` (or the older `s3://bucket/folder`) in
  the path bar. F6 between two profiles is not supported: copy instead.
- F3 view, F5 copy, F6 move / rename, F7 new folder, F8 delete work as on disk.
  Deletes on S3 are always permanent (no recycle bin).
- F4 edits a file: every save in the editor is uploaded.

## Setup: credentials

Profiles come from `~/.aws/config` and `~/.aws/credentials` (Windows: `%USERPROFILE%\.aws\`).
Per profile, first match wins:

1. Environment `AWS_ACCESS_KEY_ID` + `AWS_SECRET_ACCESS_KEY` (+ `AWS_SESSION_TOKEN`), for the
   default profile (`AWS_PROFILE`, else `default`).
2. Keys in the profile (`aws_access_key_id` / `aws_secret_access_key`).
3. SSO, `aws login`, `credential_process` and role profiles: temporary keys from the **AWS CLI
   v2** (`aws` on PATH).

**Expired credentials**: Commander shows "Credentials expired" and the exact command it will run
(e.g. `aws sso login --profile work`). **Log in** (Enter) runs it (the browser opens), then
**Retry** (R). Only `aws` is ever run this way. Static keys have no login button: renew them.

```ini
[default]
aws_access_key_id = AKIA...
aws_secret_access_key = ...
```

Region: `AWS_REGION`, `AWS_DEFAULT_REGION`, the profile's `region`, else `us-east-1`. Buckets in
other regions are followed automatically.

## Config keys

| Setting | Meaning |
|---|---|
| `AWS_ENDPOINT_URL` / `AWS_ENDPOINT_URL_S3` (env) or `endpoint_url` (profile) | S3-compatible server, e.g. `http://localhost:9000`; path-style addressing becomes the default |
| `COMMANDER_S3_PATH_STYLE=0\|1` (env) | Force virtual-host / path-style addressing |
| `AWS_PROFILE` (env) | Which profile to read |
| `download_parallel` (`s3.toml`) | Ranged GETs at once per downloaded file, 1..32, default 8 (1 = one plain GET) |
| `download_chunk_mib` (`s3.toml`) | Chunk size in MiB, 1..256, default 8; memory per file ~ (parallel + 1) x chunk; parallel is lowered so that stays <= 1 GiB |

`s3.toml` sits next to Commander's `config.toml` (`%APPDATA%\commander`, `~/.config/commander`;
env `COMMANDER_S3_CONFIG` overrides). Objects bigger than one chunk download in parallel,
every chunk pinned to the object's ETag: an object changed during a download fails cleanly.

## Limitations

- Not supported: instance / container roles (IMDS / ECS).
- Credentials are read once per connection: restart Commander after changing them.
- Folders are key prefixes: an empty folder exists only while it holds a marker object.
